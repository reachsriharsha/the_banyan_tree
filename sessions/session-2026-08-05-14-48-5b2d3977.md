## What a feature-flag override does

Each flag has three layers, in precedence order:

1. **Default** — baked into the code (`FLAGS` registry).
2. **Global toggle** — the operator flips the flag ON/OFF for *every* school at once.
3. **Per-school override** — forces a specific value for *one* school, which **wins over** the global setting for that school only.

**Example.** Flag `online_pay`, global = **ON** (all schools can pay online). Sunrise International has payment disputes, so you add an override: `online_pay = OFF for Sunrise`. Result: every school still has it ON, but Sunrise has it OFF. Remove the override and Sunrise falls back to the global ON. That "override a school…" dropdown on each flag card is how you pick *which* school to add such an override for.

## What each option would do when you arrive from Sunrise's detail page (`?tenant=sunrise`)

| Option | Concrete behavior | Cost |
|---|---|---|
| **Focused-school banner** | A banner "Showing overrides for **Sunrise**" appears. Each flag card highlights Sunrise's current override state (or "no override → follows global ON"), and its dropdown is pre-set to Sunrise so one click adds an override. You see, at a glance, *every* flag's effective value for Sunrise. | More work — new page-level UI |
| **Seed each card's dropdown** | No banner. Each flag card's "override a school…" dropdown simply defaults to Sunrise, so you don't re-pick before clicking "add override." Cards where Sunrise *already* has an override won't list it (it's filtered out — you can't add a second override). | Minimal |
| **SMS only, skip Flags** | Flags link stays a plain jump; nothing preselected. | Smallest |

My recommendation: **Focused-school banner** — it's the only one that answers the real question you'd have arriving from a school's page ("what are *this* school's flag settings?"), rather than just pre-filling a dropdown.
