## Assistant (2026-08-02T08:59:35)

Here's what happens in the database when an admin generates invoices (`POST /invoices/generate`).

## Tables written, in order

| # | Table | DB | Op | Rows | What's written |
|---|-------|-----|-----|------|----------------|
| 1 | **`invoices`** | tenant | INSERT | one per student invoiced | `student_id`, `academic_year_id`, `fee_installment_id`, `amount` (after concessions), `late_fee_amount`, `due_date`, `status="pending"` |
| 2 | **`invoice_line_items`** | tenant | INSERT | one per fee head, per invoice | `invoice_id`, `fee_head_id`, `amount` (gross), `concession_amount` (discount) |
| 3 | **`message_log`** | tenant | INSERT | 0–N per student (one per notification channel) | `channel`, `template_id`, `target_id=student`, `channel_address` (guardian phone/email), `status="queued"` — this is the outbox; nothing is sent yet |
| 4 | **`audit_events`** | tenant | INSERT | exactly 1 per request | `event="fees.invoice.generated"`, `target=fee_installment`, `after={generated, skipped_existing, skipped_inactive}` |
| 5 | **`idempotency_keys`** | **control** | INSERT | 1 per request | the Idempotency-Key + a snapshot of the full response |

## Key facts

- **Atomicity:** tables 1–4 (all tenant DB) commit together in **one transaction** — invoices, their line items, the queued notifications, and the audit row all land or none do.
- **`idempotency_keys` is separate** — control DB, its own commit, after the tenant commit. It's what makes a retried request return the same result instead of double-billing.
- **Idempotent by design:** students who already have a live (non-cancelled) invoice for that installment are **skipped**, not duplicated. A partial unique index on `(student_id, fee_installment_id) WHERE status != 'cancelled'` is the backstop.
- **`dry_run=true` writes nothing** — returns a preview (counts + per-student breakdown + total) only.
- **No money leaves the system here.** Notifications sit as `queued` rows in `message_log`; a separate dispatcher drains them later.

So per invoiced student you get: **1 `invoices` row + N `invoice_line_items` rows (one per fee head) + up to a couple `message_log` rows**, plus **one shared `audit_events` row** and **one `idempotency_keys` row** for the whole batch.
