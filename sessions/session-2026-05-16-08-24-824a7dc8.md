# Company Quick Scan (SOIC 30-Minute Deep Dive)

Purpose: Take a company name (or uploaded annual report) and produce a structured fundamental verdict in ~30 minutes of analysis time. This is the **first filter** before any deeper research.

## Inputs required
- Company name + ticker (NSE/BSE for India, NYSE/NASDAQ for US)
- Latest Annual Report PDF (ask user to upload, or fetch from BSE/company IR page)
- Optional: Screener.in URL (India) or 10-K link (US)

If the AR is missing, STOP and ask the user to provide it. Do not fabricate financials.

## Workflow (run in order)

### Step 1 — Locate the Annual Report
Confirm the most recent AR (FY ending). For India use BSE filings; for US use SEC EDGAR 10-K.

### Step 2 — 12-Point Annual Report Analysis
Read the AR and answer:
1. What does the company do? (1 paragraph, plain English)
2. Business segments and revenue mix (%)
3. Geography mix (%)
4. Customer concentration (top 5 / top 10)
5. Promoter / management background and pledging
6. Capex cycle status (expansion, maintenance, idle)
7. Working capital trend (debtor days, inventory days, cash conversion)
8. Debt position and interest coverage
9. Key risks disclosed by management
10. Related-party transactions (size, nature, recurring?)
11. Auditor changes / qualifications in last 3 years
12. Strategy and guidance stated by Chairman/MD letter

### Step 3 — 10-Point Forensic Red Flag Scan
Rate each as **GREEN / AMBER / RED**:
1. Cash flow vs PAT divergence (CFO/PAT < 0.7 over 3 yrs = RED)
2. Receivables growing faster than revenue
3. Inventory growing faster than revenue
4. Contingent liabilities vs net worth
5. Promoter pledging trend
6. Auditor qualifications
7. Related-party transaction size
8. Goodwill / intangible bloat
9. Frequent equity dilution
10. Subsidiary losses absorbed quietly

### Step 4 — Piotroski F-Score + DuPont
Compute Piotroski (0–9) and decompose ROE = Net Margin × Asset Turnover × Leverage. Compare 3-year trend.

### Step 5 — Bear Case
Write the strongest argument **against** owning the stock in 5 bullets. Be honest and aggressive.

### Step 6 — Verdict
One of: **BUY-WORTHY (deep-dive next)**, **WATCH (revisit on trigger)**, **PASS (do not pursue)**. Justify in 3 sentences.

## Critical data rules
- **Never calculate P/E from quarterly PAT.** Always pull TTM P/E from Screener.in (India) or the 10-K/quarterly filings (US).
- **10% divergence rule**: If your computed metric diverges >10% from Screener.in, trust Screener.in and re-check your math.
- All financial figures must cite the source page of the AR or Screener URL.

## Output format
Save as `<TICKER>_quick_scan_<YYYYMMDD>.md` in the user's workspace folder. Use the headings above. End with the Verdict and a list of follow-up questions for a deeper dive.

## Composability
After this skill: run `concall-analyzer` on last 4 concall transcripts, then `growth-triggers-onepager` if verdict is BUY-WORTHY or WATCH.

# Concall Analyzer

Three modes — pick based on input count and user intent.

## Mode A — Concall Brief (default for 1 transcript, fast)
9 sections:
1. Headline numbers (revenue, EBITDA, PAT, margin, YoY/QoQ)
2. Segment performance
3. Demand commentary
4. Margin drivers / pressures
5. Capex and balance sheet update
6. Guidance (quote management verbatim)
7. New announcements (orders, products, deals)
8. Analyst Q&A — top 3 sharp questions and management's answers
9. Key takeaway in 2 sentences

## Mode B — Concall Deep Dive (12 sections, when user asks for "deep" or single critical quarter)
Adds to Mode A:
10. Confidence Language Audit (see taxonomy below)
11. What was NOT answered / dodged questions
12. Changes in tone vs prior call

## Mode C — Walk the Talk (when 4+ concalls provided)
Build a credibility scorecard:
- Extract every forward statement from concall N-3
- Check if it played out by concall N
- Score **+1 for beat**, **0 for partial**, **-1 for miss**
- Aggregate score → Management Credibility Rating (HIGH / MEDIUM / LOW)
- Flag any pattern of repeated optimism without delivery.

## Confidence Language Taxonomy (apply in all modes)
- **HIGH conviction**: "We will", "We have", "We are", "This year we deliver"
- **MEDIUM conviction**: "We expect", "We should", "We are confident", "We anticipate"
- **LOW conviction**: "May", "Could", "Endeavor to", "Aspire", "Hopefully"

Tag each guidance statement with HIGH/MEDIUM/LOW and warn the user when LOW-conviction language is used for material claims.

## Inputs
- 1+ concall transcript files (PDF or text). If only company name is given, ask the user to upload transcripts (Quartr / company IR page).

## Output
Filename: `<TICKER>_concall_<QUARTER>_<mode>.md` saved in the workspace folder. For Walk the Talk: `<TICKER>_walk_the_talk_<YYYYMMDD>.md`.

## Critical rules
- Always quote management verbatim in quotation marks for guidance statements; never paraphrase guidance.
- Cite the page or timestamp of each quote.
- Do not invent numbers — if the transcript doesn't say it, write "not disclosed".

# Growth Triggers 1-Pager

Produces a single-page investment thesis modeled on SOIC's Acutaas Chemicals format. The output must fit on roughly one page when printed.

## Inputs
- Company name + ticker
- Recent annual report and last 2-4 concall transcripts (or output of `company-quick-scan` and `concall-analyzer`)
- Any sector/industry reports the user has uploaded

## Conviction tag rules (BE DISCIPLINED)
- **HIGH**: Capacity already commissioned, contracts signed, customer named, regulatory approval received. Money is essentially on the way.
- **MEDIUM**: Capex announced with timelines, qualification in progress, sector tailwind backed by data.
- **OPTIONALITY**: Plausible upside but no commitment from management. Cannot be the main reason to own.

If you cannot find concrete evidence in filings/concalls, downgrade the tag. Never label OPTIONALITY items as HIGH.

## Output template

```
# <Company> — Growth Triggers 1-Pager
*As of <date> | CMP: ₹X | Mcap: ₹Y cr | Source: Screener.in*

## Business in one line
<plain-English description>

## The 3-7 Growth Triggers
### Trigger 1: <name> [HIGH | MEDIUM | OPTIONALITY]
- What: <2 lines>
- Evidence: <quote from concall/AR with citation>
- Quantum: <revenue / margin impact estimate>
- Timeline: <FY26 / FY27 / etc.>

### Trigger 2: ...
(repeat)

## Trigger Scoreboard
| # | Trigger | Conviction | Quantum (₹ cr) | Timeline | Status |
|---|---------|------------|----------------|----------|--------|
| 1 | ...     | HIGH       | 200            | FY26     | On track |
| 2 | ...     | MEDIUM     | ...            | ...      | ...    |

## What can break the thesis (top 3 risks)
1. ...
2. ...
3. ...

## Verdict
<2-3 sentences. Sum of HIGH + MEDIUM triggers should justify the thesis on their own; OPTIONALITY is upside.>
```

## Output file
Save as `<TICKER>_growth_triggers_<YYYYMMDD>.md` in the workspace folder.

## Critical rules
- Every trigger must cite a specific source (AR page, concall date+page).
- Do not include sector platitudes ("China+1", "premiumisation") as triggers unless tied to a specific contract or capex.
- Use Screener.in for CMP and Mcap; never compute valuation multiples from quarterly PAT.

# Investment Report (Static HTML)

Purpose: Fuse the three per-company markdown artifacts into one static, offline-viewable HTML file. Function over form — readable, color-coded, no login or server required.

## Inputs required
For a single company `<TICKER>`:
1. `<TICKER>_quick_scan_*.md` (from `company-quick-scan`)
2. `<TICKER>_concall_*.md` or `<TICKER>_walk_the_talk_*.md` (from `concall-analyzer`)
3. `<TICKER>_growth_triggers_*.md` (from `growth-triggers-onepager`)

If any of the three is missing, ask the user to run the corresponding skill first or upload the file. Do not invent content.

## What the HTML must contain

### 1. Header strip
Company name, ticker, CMP, Mcap, sector, report date, and the **Verdict badge** from the quick scan. Badge colors:
- BUY-WORTHY → green
- WATCH → amber
- PASS → red

### 2. Executive summary (top of page, always visible)
- Verdict + one-line business description
- Piotroski score (number + bar)
- Management credibility (HIGH/MEDIUM/LOW from Walk-the-Talk if available)
- Count of HIGH / MEDIUM / OPTIONALITY growth triggers

### 3. Structured data sections (parsed from the markdowns — not just dumped)
For each of the 3 source files, extract every data point and render as tables + charts. Do NOT just paste markdown; parse it into structured HTML.

**From quick_scan.md — render:**
- 12-point AR analysis → 2-column table
- 10-point Forensic Red Flag Scan → table with GREEN/AMBER/RED cell backgrounds
- Piotroski F-Score → horizontal bar (0–9) using inline SVG or Chart.js
- DuPont decomposition (Net margin, Asset turnover, Leverage, ROE) → grouped bar chart for 3 years
- Bear case → red-bordered callout box

**From concall / walk-the-talk.md — render:**
- Headline numbers table (Revenue, EBITDA, PAT, Margin — QoQ/YoY) with up/down arrows
- Revenue/EBITDA/PAT line chart across available quarters
- Guidance statements table with a Confidence column color-coded HIGH (green) / MEDIUM (amber) / LOW (red)
- Walk-the-Talk scorecard (beat +1 / miss -1) → stacked bar + running credibility total

**From growth_triggers.md — render:**
- Trigger Scoreboard table with Conviction column color-coded HIGH (green) / MEDIUM (amber) / OPTIONALITY (grey)
- Horizontal bar chart of Quantum (₹ cr) per trigger, colored by conviction
- Risks → red callout list

### 4. Collapsible raw markdown sections
At the bottom of the page, three `<details>` elements (native HTML, no JS needed) labeled:
- "Full Quick Scan markdown"
- "Full Concall Analysis markdown"
- "Full Growth Triggers markdown"

Each `<details>` contains the original markdown rendered inside `<pre>` or passed through a lightweight markdown renderer (use `marked.min.js` from cdnjs if markdown formatting is desired; otherwise `<pre>` is fine).

### 5. Footer
Timestamp, list of source files consumed, and the disclaimer: "Research only. Not investment advice."

## Technical implementation

- **Single file**: everything (HTML + CSS + JS + data) in one `.html` file so it works offline.
- **Charts**: Use Chart.js from `https://cdnjs.cloudflare.com/ajax/libs/Chart.js/4.4.0/chart.umd.min.js`. Keep chart count minimal — only where numbers need visual comparison.
- **Styling**: Plain CSS, system font stack, max-width 1100px, neutral background. No heavy framework. A small color palette only:
  - Green `#16a34a`, Amber `#d97706`, Red `#dc2626`, Grey `#6b7280`, Neutral bg `#f9fafb`, Text `#111827`.
- **Tables**: Simple bordered tables with zebra striping. Color-coded cells use background tint, not full saturation, so text stays readable.
- **Collapsibles**: Native `<details><summary>`; no custom JS.
- **No external fonts, no tracking, no network calls except the Chart.js CDN.**

## Workflow

1. Read all 3 input markdown files.
2. Parse each into a JS object literal embedded at the top of the HTML `<script>` block (so the page is self-contained).
3. Render the structured sections from the parsed object.
4. At the bottom, embed the raw markdown strings as template literals inside the collapsibles.
5. Write the file as `<TICKER>_report_<YYYYMMDD>.html` in the user's workspace folder.
6. Open/present it with `mcp__cowork__present_files` so the user can click through.

## Critical rules
- **Never fabricate numbers.** If a value is missing in the source markdowns, render "n/a" — do not interpolate.
- **Preserve citations.** Any quote or metric that had a source page in the markdown should keep the citation visible in a small muted span.
- **Function > form.** Do not spend effort on hero images, gradients, animations, or decorative icons. The user has explicitly deprioritized visual polish.
- **Deterministic parsing.** The three input skills follow fixed templates — parse by headings (e.g., `## Trigger Scoreboard`) rather than by fuzzy matching.
- **Offline-viewable is a hard requirement** except for the Chart.js CDN script tag.

## Composability
Run after `company-quick-scan` + `concall-analyzer` + `growth-triggers-onepager`. This is the final step of the per-company research pipeline.
