### 4. Login procedures

All auth endpoints are under **`/api/v1/auth`** (base `http://localhost:8000`).

**(a) Dev-login endpoint (fastest — no OTP).** Requires `AKSHARA_DEV_AUTH=1` (returns **404** when unset — this is the prod guard). `POST /api/v1/auth/dev-login` accepts **one of**:
- `{"email": "principal@demoschool.test"}` — mints a token for that seeded principal (404 if unknown).
- `{"tenant": "demoschool", "role": "teacher"}` — mints a synthetic token for that role in that tenant (`tenant` = slug **or** id; unknown tenant → 404, invalid role → 400). No seeded user needed — works for any provisioned tenant incl. `stg-*`.
- `{"role": "super_admin"}` — platform-scope token, `tenant` omitted/ignored.

Response: `200` + `{"access": "&lt;JWT&gt;"}` and an `HttpOnly` refresh cookie. Send the JWT as `Authorization: Bearer &lt;access&gt;`. In the web UI this is the **`auth-dev-login`** button (needs `VITE_DEV_AUTH=1`). Valid roles: `super_admin`, `school_admin`, `teacher`, `parent`.

Example:
```
curl -X POST http://localhost:8000/api/v1/auth/dev-login \
  -H 'Content-Type: application/json' \
  -d '{"tenant":"demoschool","role":"teacher"}'
```

**(b) Real email OTP (staff/admin/super-admin).**
1. `POST /api/v1/auth/otp/request` with `{"email": "&lt;addr&gt;"}` → always `202` (no user enumeration). Rate-limited: 2nd request within 60s → `429`; &gt;5/hr → `429`.
2. Open **http://localhost:8025** (Mailpit) and read the 6-digit code from the "Your Akshara sign-in code" email (code is never in the logs).
