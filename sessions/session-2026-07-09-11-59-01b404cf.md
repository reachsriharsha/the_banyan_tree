## Assistant (2026-07-09T12:00:26)

Good project to brainstorm. Let me lay out the design space, then a few decisions worth settling before I write the design doc.

**The pipeline has 5 stages:**

1. **Discover** — scan sources for ~1 hour at a scheduled time, collect positive posts
2. **Curate** — LLM scores candidates (positivity, virality potential, relevance), dedupes
3. **Acquire** — download media, store post + metadata in a local queue (SQLite)
4. **Publish** — drip-post through the day at optimal times, per platform
5. **Track** — log engagement to learn what grows subscribers

**Key architectural fork — how to post to X:**

| Option | Cost | Reliability | Ban risk |
|---|---|---|---|
| A. X API (official) | Free tier ~500 posts/mo | High | None |
| B. Playwright + persistent profile (login once, reuse session) | Free | Medium — breaks when X changes UI | Real — X actively detects automation; monetized accounts get suspended |
| C. Browser agent (OpenClaw / Claude in Chrome style) | LLM cost per post | Medium | Same as B |

The uncomfortable truth: since your goal is **monetization**, account suspension is the existential risk. X's ToS prohibits browser automation; the API is the sanctioned path and its free write tier likely covers your volume. The best hybrid is often: **browser/Playwright for discovery** (API reads are expensive — $200/mo tier), **API for posting** (free, safe).

**Second fork — content strategy.** Downloading others' media and re-uploading as your own post is a copyright problem and X can demonetize for unoriginal content. Alternatives: native retweet/quote (safe, but grows the original author more than you), or use scanned posts as *inspiration* and have the LLM generate original positive content + your own media. The last option is what actually builds a subscriber base.

**Orchestration:** a full LangChain agent is overkill for the publish loop (deterministic cron job is more reliable). Where an agent earns its keep is curation — deciding what's genuinely positive and worth posting. I'd suggest LangGraph for a structured pipeline with LLM nodes, not a free-roaming agent.
