# Listed Company Filings Downloader

## What this skill does

Given a listed company (name or ticker), this skill:

1. **Resolves identity** — figures out the correct ticker and exchange (NSE, BSE, NASDAQ, NYSE). Fails loudly if the company name is ambiguous.
2. **Fetches a filings index** — pulls the list of all corporate disclosures the company has filed on its primary exchange over the relevant lookback window.
3. **Filters to business-relevant filings only** — keeps annual reports, earnings concall transcripts + matching IPs, standalone investor presentations, and credit rating reports. Logs everything else (shareholding patterns, AGM notices, insider trading disclosures, trading window closures, etc.) in `_manifest.json` under `skipped[]` so nothing is silently lost.
4. **Downloads each kept filing** into an organized folder tree with consistent slug-based filenames.
5. **Writes a manifest** summarizing what was kept, what was skipped, what failed, and where each file came from.

This is the *acquisition* step that feeds downstream analysis skills (`company-quick-scan`, `concall-analyzer`, `growth-triggers-onepager`). It does not analyze the filings — it just gathers them cleanly.

## Why these design choices

A listed company files dozens of documents a year, most of which are governance plumbing (shareholding pattern, AGM notices, trading window closures, related-party transaction summaries) rather than substantive business information. A naive "download everything" approach buries the analyst in noise. A naive "AI-judge each filing" approach is slow, expensive, and unreliable.

The pragmatic answer is a **category whitelist** — every Indian exchange categorizes its filings (the BSE "Subcategory" field, NSE's announcement type), and EDGAR uses standardized form types (10-K, 10-Q, 8-K, etc.). Filtering by category captures ~95% of what matters at near-zero cost. The skipped items go in the manifest with their URLs, so an analyst who needs something specific can fetch it manually without re-running the skill.

## Inputs

The skill expects the user to have supplied:

- A **company name** (e.g., "Reliance Industries") OR
- A **ticker** with optional exchange suffix (e.g., `RELIANCE.NS`, `RELIANCE.BO`, `AAPL`, `500325.BO`)

If the name is ambiguous (more than one strong match), STOP and return a candidate list to the user. Do not guess. The cost of downloading filings for the wrong company is high (wasted time + bad downstream analysis); the cost of asking once is low.

Optional flags the user may specify:
- `--years N` — override the default lookback (defaults: 5 for annual, 2 for concalls/IPs, 4-most-recent for ratings)
- `--include-skipped` — also download items that would normally be in the skipped list

## Workflow

Follow this sequence. Each step has a dedicated reference file or script — load them only when you reach that step, so context stays lean.

### Step 1: Resolve the company to a ticker + exchange

Use `scripts/ticker_resolver.py` to map name → ticker + exchange. It tries (in order): exact ticker match, yfinance search, EDGAR full-text company lookup, NSE/BSE name search. It returns either:
- A single confident match → proceed
- Multiple candidates → STOP, present them to the user, ask which one. Do not auto-pick.
- No match → STOP, tell the user the company couldn't be found and suggest they provide the ticker.

```bash
python scripts/ticker_resolver.py "Reliance Industries"
# Output: {"ticker": "RELIANCE.NS", "exchange": "NSE", "name": "Reliance Industries Limited", "confidence": "high"}
```

### Step 2: Set up the output directory

The slug rule: lowercase, hyphenated, max ~40 chars, with exchange suffix. Examples: `reliance-industries_NSE`, `apple_NASDAQ`, `hdfc-bank_NSE`. Use the slug as the root folder name. Inside, create empty subfolders:

```
{slug}/
├── _manifest.json
├── annual_reports/
├── concalls/
│   ├── transcripts/
│   └── investor_presentation/
├── investor_presentations/
└── credit_ratings/
```

Save into the user's working directory unless they specified a different output path.

### Step 3: Fetch the filings index for the resolved exchange

Read the relevant exchange's reference file and use its client script:

- **EDGAR (US)** — read `references/edgar.md`, use `scripts/edgar_client.py`. Returns 10-K, 10-Q, 8-K, DEF 14A, ARS filings. For concall transcripts and investor presentations, also call the best-effort IR-page scraper (`scripts/ir_page_scraper.py`) since EDGAR does not host these.
- **NSE (India)** — read `references/nse.md`, use `scripts/nse_client.py`. Returns annual reports + categorized corporate announcements.
- **BSE (India)** — read `references/bse.md`, use `scripts/bse_client.py`. Returns annual reports + announcements with subcategories.

If the company is dual-listed on NSE and BSE (most Indian large caps are), prefer NSE. If NSE returns thin results, fall back to BSE for the gaps.

### Step 4: Apply the whitelist filter

Read `references/whitelist.md` for the category-by-category rules. Use `scripts/filter_whitelist.py` to partition the filings index into two arrays:

- `kept[]` — annual reports, concall transcripts, investor presentations, credit ratings
- `skipped[]` — everything else (with title, date, category, url, and a short `reason` string explaining why it was skipped)

### Step 5: Download the kept filings

Use `scripts/downloader.py`. For each kept item:

1. Construct the target path using the filename convention (see below).
2. Stream the file (don't load fully into memory — annual reports can be 50MB+).
3. On HTTP errors, retry up to 3 times with exponential backoff.
4. On persistent failure, log to `errors[]` in the manifest and continue — don't abort the whole run for one bad file.

**Filename convention:**

| Type | Pattern | Example |
|---|---|---|
| Annual report | `{slug}_AR_FY{YY}.{ext}` | `reliance-industries_AR_FY24.pdf` |
| Concall transcript | `{slug}_concall_Q{n}FY{YY}_transcript.{ext}` | `reliance-industries_concall_Q3FY24_transcript.pdf` |
| Quarterly IP | `{slug}_concall_Q{n}FY{YY}_ip.{ext}` | (stored under `concalls/investor_presentation/`) |
| Standalone IP | `{slug}_IP_{YYYY-MM}_{label}.{ext}` | `reliance-industries_IP_2024-09_capital-markets-day.pdf` |
| Credit rating | `{slug}_rating_{agency}_{YYYY-MM}.{ext}` | `reliance-industries_rating_CRISIL_2024-08.pdf` |

For US companies, fiscal year notation may differ — use `FY24` for the fiscal year ending in 2024 (Sept for Apple, Dec for most others). For Indian companies, the fiscal year is April–March, so `FY24` = April 2023–March 2024.

### Step 6: Best-effort credit rating fetch from agency sites

Exchange filings often contain only the rating *summary* (the press-release announcement), not the full *rationale* PDF. The full rationale is usually free on the agency's site. After Step 5, for each rating found in exchange filings, attempt to fetch the full rationale from the relevant agency:

- **CRISIL** — https://www.crisilratings.com (search by company name)
- **ICRA** — https://www.icra.in
- **CARE** — https://www.careratings.com
- **India Ratings** — https://www.indiaratings.co.in
- **S&P Global** — https://www.spglobal.com/ratings
- **Moody's** — https://www.moodys.com
- **Fitch** — https://www.fitchratings.com

Use `scripts/rating_agency_scraper.py`. This is best-effort: if the rationale isn't publicly accessible, keep the exchange-filed summary and note `full_rationale_unavailable: true` in the manifest entry. Do not block on this.

### Step 7: Write the manifest

Use `scripts/manifest_writer.py` to write `_manifest.json` at the root of the output directory. Schema (also documented in `references/manifest_schema.md`):

```json
{
  "company": "Reliance Industries Limited",
  "ticker": "RELIANCE.NS",
  "exchange": "NSE",
  "slug": "reliance-industries",
  "generated_at": "2026-05-15T10:30:00Z",
  "lookback": {"annual_years": 5, "concall_years": 2, "ip_years": 2, "ratings_count": 4},
  "kept": [
    {
      "type": "annual_report",
      "fiscal_year": "FY24",
      "date": "2024-06-15",
      "title": "Annual Report 2023-24",
      "source_url": "https://...",
      "local_path": "annual_reports/reliance-industries_AR_FY24.pdf",
      "size_bytes": 12345678
    }
  ],
  "skipped": [
    {
      "date": "2024-04-10",
      "title": "Shareholding Pattern as on 31-03-2024",
      "category": "Shareholding Pattern",
      "source_url": "https://...",
      "reason": "category not in business-relevance whitelist"
    }
  ],
  "errors": [
    {
      "phase": "download",
      "item": "Q1 FY24 Concall Transcript",
      "url": "https://...",
      "error": "HTTP 403 after 3 retries"
    }
  ]
}
```

### Step 8: Summarize for the user

Print a short summary to the chat:
- Company, ticker, exchange
- Counts: `kept` total + breakdown by type, `skipped` total, `errors` total
- A `computer://` link to the output folder (so the user can open it in Finder)
- Highlight any gaps: "No concall transcripts found for FY22 — these may pre-date the company's transcript-disclosure practice."

## When the data isn't there

Be honest in the manifest and summary about what wasn't found:

- **Concall transcripts before 2018-19** are often missing from Indian exchanges — companies started filing them systematically only after SEBI tightened disclosure norms. Note the gap, don't fabricate.
- **US small/mid caps** may not have investor presentations on EDGAR and may have a thin IR page. The IR-page scraper is best-effort.
- **Small-cap credit ratings** may have only 1-2 agencies covering them (CRISIL + ICRA most common in India). Don't pad the count with stale ratings.

## Things to avoid

- **Do not** use computer:// browser tools to scrape NSE — use the JSON API endpoints documented in `references/nse.md`. NSE's HTML pages have aggressive anti-bot measures; their JSON endpoints are more stable when you send the right cookies and headers.
- **Do not** silently download files whose categories aren't on the whitelist. If a filing seems important but doesn't match the whitelist (e.g., a major announcement filed under a generic "Other" category), surface it in the summary as "potentially material but uncategorized" rather than just dumping it into one of the typed folders.
- **Do not** retry forever. Three attempts with exponential backoff, then log the failure to `errors[]` and move on.
- **Do not** assume the user wants to wait through a 200-MB annual-report PDF download for every fiscal year if they're impatient. If the user says "quick" or "preview" or sets `--list-only`, fetch the index and write the manifest but skip the actual downloads.

## Composes with other skills

Outputs from this skill are designed to be fed into:
- `concall-analyzer` — point it at `concalls/transcripts/` for the Walk-the-Talk analysis
- `company-quick-scan` — point it at the latest `annual_reports/*.pdf`
- `growth-triggers-onepager` — uses recent investor presentations and concalls

The clean folder structure + manifest is the contract between this skill and those downstream skills.

# Company Quick Scan (SOIC 30-Minute Deep Dive)

Purpose: Take a company name (or uploaded annual report) and produce a structured fundamental verdict in ~30 minutes of analysis time. This is the **first filter** before any deeper research.

## Inputs required
- Company name + ticker (NSE/BSE for India, NYSE/NASDAQ for US)
- Latest Annual Report PDF (ask user to upload, or fetch from BSE/company IR page)
- Optional: Screener.in URL (India) or 10-K link (US)

If the AR is missing, STOP and ask the user to provide it. Do not fabricate financials.

## Workflow (run in order)

### Step 1 — Locate the Annual Report
Confirm the most recent AR (FY ending). For India use BSE filings; for US use SEC EDGAR 10-K.

### Step 2 — 12-Point Annual Report Analysis
Read the AR and answer:
1. What does the company do? (1 paragraph, plain English)
2. Business segments and revenue mix (%)
3. Geography mix (%)
4. Customer concentration (top 5 / top 10)
5. Promoter / management background and pledging
6. Capex cycle status (expansion, maintenance, idle)
7. Working capital trend (debtor days, inventory days, cash conversion)
8. Debt position and interest coverage
9. Key risks disclosed by management
10. Related-party transactions (size, nature, recurring?)
11. Auditor changes / qualifications in last 3 years
12. Strategy and guidance stated by Chairman/MD letter

### Step 3 — 10-Point Forensic Red Flag Scan
Rate each as **GREEN / AMBER / RED**:
1. Cash flow vs PAT divergence (CFO/PAT < 0.7 over 3 yrs = RED)
2. Receivables growing faster than revenue
3. Inventory growing faster than revenue
4. Contingent liabilities vs net worth
5. Promoter pledging trend
6. Auditor qualifications
7. Related-party transaction size
8. Goodwill / intangible bloat
9. Frequent equity dilution
10. Subsidiary losses absorbed quietly

### Step 4 — Piotroski F-Score + DuPont
Compute Piotroski (0–9) and decompose ROE = Net Margin × Asset Turnover × Leverage. Compare 3-year trend.

### Step 5 — Bear Case
Write the strongest argument **against** owning the stock in 5 bullets. Be honest and aggressive.

### Step 6 — Verdict
One of: **BUY-WORTHY (deep-dive next)**, **WATCH (revisit on trigger)**, **PASS (do not pursue)**. Justify in 3 sentences.

## Critical data rules
- **Never calculate P/E from quarterly PAT.** Always pull TTM P/E from Screener.in (India) or the 10-K/quarterly filings (US).
- **10% divergence rule**: If your computed metric diverges >10% from Screener.in, trust Screener.in and re-check your math.
- All financial figures must cite the source page of the AR or Screener URL.

## Output format
Save as `<TICKER>_quick_scan_<YYYYMMDD>.md` in the user's workspace folder. Use the headings above. End with the Verdict and a list of follow-up questions for a deeper dive.

## Composability
After this skill: run `concall-analyzer` on last 4 concall transcripts, then `growth-triggers-onepager` if verdict is BUY-WORTHY or WATCH.

# Growth Triggers 1-Pager

Produces a single-page investment thesis modeled on SOIC's Acutaas Chemicals format. The output must fit on roughly one page when printed.

## Inputs
- Company name + ticker
- Recent annual report and last 2-4 concall transcripts (or output of `company-quick-scan` and `concall-analyzer`)
- Any sector/industry reports the user has uploaded

## Conviction tag rules (BE DISCIPLINED)
- **HIGH**: Capacity already commissioned, contracts signed, customer named, regulatory approval received. Money is essentially on the way.
- **MEDIUM**: Capex announced with timelines, qualification in progress, sector tailwind backed by data.
- **OPTIONALITY**: Plausible upside but no commitment from management. Cannot be the main reason to own.

If you cannot find concrete evidence in filings/concalls, downgrade the tag. Never label OPTIONALITY items as HIGH.

## Output template

```
# <Company> — Growth Triggers 1-Pager
*As of <date> | CMP: ₹X | Mcap: ₹Y cr | Source: Screener.in*

## Business in one line
<plain-English description>

## The 3-7 Growth Triggers
### Trigger 1: <name> [HIGH | MEDIUM | OPTIONALITY]
- What: <2 lines>
- Evidence: <quote from concall/AR with citation>
- Quantum: <revenue / margin impact estimate>
- Timeline: <FY26 / FY27 / etc.>

### Trigger 2: ...
(repeat)

## Trigger Scoreboard
| # | Trigger | Conviction | Quantum (₹ cr) | Timeline | Status |
|---|---------|------------|----------------|----------|--------|
| 1 | ...     | HIGH       | 200            | FY26     | On track |
| 2 | ...     | MEDIUM     | ...            | ...      | ...    |

## What can break the thesis (top 3 risks)
1. ...
2. ...
3. ...

## Verdict
<2-3 sentences. Sum of HIGH + MEDIUM triggers should justify the thesis on their own; OPTIONALITY is upside.>
```

## Output file
Save as `<TICKER>_growth_triggers_<YYYYMMDD>.md` in the workspace folder.

## Critical rules
- Every trigger must cite a specific source (AR page, concall date+page).
- Do not include sector platitudes ("China+1", "premiumisation") as triggers unless tied to a specific contract or capex.
- Use Screener.in for CMP and Mcap; never compute valuation multiples from quarterly PAT.

# Investment Report (Static HTML)

Purpose: Fuse the three per-company markdown artifacts into one static, offline-viewable HTML file. Function over form — readable, color-coded, no login or server required.

## Inputs required
For a single company `<TICKER>`:
1. `<TICKER>_quick_scan_*.md` (from `company-quick-scan`)
2. `<TICKER>_concall_*.md` or `<TICKER>_walk_the_talk_*.md` (from `concall-analyzer`)
3. `<TICKER>_growth_triggers_*.md` (from `growth-triggers-onepager`)

If any of the three is missing, ask the user to run the corresponding skill first or upload the file. Do not invent content.

## What the HTML must contain

### 1. Header strip
Company name, ticker, CMP, Mcap, sector, report date, and the **Verdict badge** from the quick scan. Badge colors:
- BUY-WORTHY → green
- WATCH → amber
- PASS → red

### 2. Executive summary (top of page, always visible)
- Verdict + one-line business description
- Piotroski score (number + bar)
- Management credibility (HIGH/MEDIUM/LOW from Walk-the-Talk if available)
- Count of HIGH / MEDIUM / OPTIONALITY growth triggers

### 3. Structured data sections (parsed from the markdowns — not just dumped)
For each of the 3 source files, extract every data point and render as tables + charts. Do NOT just paste markdown; parse it into structured HTML.

**From quick_scan.md — render:**
- 12-point AR analysis → 2-column table
- 10-point Forensic Red Flag Scan → table with GREEN/AMBER/RED cell backgrounds
- Piotroski F-Score → horizontal bar (0–9) using inline SVG or Chart.js
- DuPont decomposition (Net margin, Asset turnover, Leverage, ROE) → grouped bar chart for 3 years
- Bear case → red-bordered callout box

**From concall / walk-the-talk.md — render:**
- Headline numbers table (Revenue, EBITDA, PAT, Margin — QoQ/YoY) with up/down arrows
- Revenue/EBITDA/PAT line chart across available quarters
- Guidance statements table with a Confidence column color-coded HIGH (green) / MEDIUM (amber) / LOW (red)
- Walk-the-Talk scorecard (beat +1 / miss -1) → stacked bar + running credibility total

**From growth_triggers.md — render:**
- Trigger Scoreboard table with Conviction column color-coded HIGH (green) / MEDIUM (amber) / OPTIONALITY (grey)
- Horizontal bar chart of Quantum (₹ cr) per trigger, colored by conviction
- Risks → red callout list

### 4. Collapsible raw markdown sections
At the bottom of the page, three `<details>` elements (native HTML, no JS needed) labeled:
- "Full Quick Scan markdown"
- "Full Concall Analysis markdown"
- "Full Growth Triggers markdown"

Each `<details>` contains the original markdown rendered inside `<pre>` or passed through a lightweight markdown renderer (use `marked.min.js` from cdnjs if markdown formatting is desired; otherwise `<pre>` is fine).

### 5. Footer
Timestamp, list of source files consumed, and the disclaimer: "Research only. Not investment advice."

## Technical implementation

- **Single file**: everything (HTML + CSS + JS + data) in one `.html` file so it works offline.
- **Charts**: Use Chart.js from `https://cdnjs.cloudflare.com/ajax/libs/Chart.js/4.4.0/chart.umd.min.js`. Keep chart count minimal — only where numbers need visual comparison.
- **Styling**: Plain CSS, system font stack, max-width 1100px, neutral background. No heavy framework. A small color palette only:
  - Green `#16a34a`, Amber `#d97706`, Red `#dc2626`, Grey `#6b7280`, Neutral bg `#f9fafb`, Text `#111827`.
- **Tables**: Simple bordered tables with zebra striping. Color-coded cells use background tint, not full saturation, so text stays readable.
- **Collapsibles**: Native `<details><summary>`; no custom JS.
- **No external fonts, no tracking, no network calls except the Chart.js CDN.**

## Workflow

1. Read all 3 input markdown files.
2. Parse each into a JS object literal embedded at the top of the HTML `<script>` block (so the page is self-contained).
3. Render the structured sections from the parsed object.
4. At the bottom, embed the raw markdown strings as template literals inside the collapsibles.
5. Write the file as `<TICKER>_report_<YYYYMMDD>.html` in the user's workspace folder.
6. Open/present it with `mcp__cowork__present_files` so the user can click through.

## Critical rules
- **Never fabricate numbers.** If a value is missing in the source markdowns, render "n/a" — do not interpolate.
- **Preserve citations.** Any quote or metric that had a source page in the markdown should keep the citation visible in a small muted span.
- **Function > form.** Do not spend effort on hero images, gradients, animations, or decorative icons. The user has explicitly deprioritized visual polish.
- **Deterministic parsing.** The three input skills follow fixed templates — parse by headings (e.g., `## Trigger Scoreboard`) rather than by fuzzy matching.
- **Offline-viewable is a hard requirement** except for the Chart.js CDN script tag.
