The parent is seeing the full roster because the `parent` role legitimately passes every gate on the way to that page — this isn't a filter bug on the Students page, it's an over-broad RBAC grant that dates back to the original permission matrix. Here's the chain:

## Root cause: the `parent` role holds admin-plane permission keys

In `backend/app/authz/catalog.py:112-123`, the parent role grants `students:read`, `fees:read`, `attendance:read`, `communication:read`, `circulars:read` — the same keys that gate the **admin** surface. These have been there since the RBAC matrix first landed (`47fb2ab`, m1_09), before the parent-scoped keys existed. When m6_03 later introduced the properly self-scoped `parent:children:read` (the catalog comment even says "a parent reads only their own data... kept out of the school_admin blanket"), the old broad grants were never removed.

Everything downstream behaves "correctly" given that grant:

1. **Sidebar** (`frontend/src/components/layout/Sidebar.tsx:36`): the Students nav item is shown to anyone holding `students:read` — so the parent sees Students, Fees, Attendance, Communication, Circulars in the sidebar (exactly the five broad keys they hold, which matches your screenshot).

2. **Frontend router** (`frontend/src/App.tsx:87`): the `/admin/students` branch runs for *any* tenant user — the `isParent` branch at line 177 only kicks in for `/`, `/fees`, `/attendance`, `/circulars`, `/profile`. The comments throughout App.tsx say "the backend's gate is the real authority," which is a sound design — except the backend gate lets parents through.

3. **Backend endpoint** (`backend/app/modules/students/router.py:302-325`): `GET /api/v1/admin/students` requires only `students:read` and does no row-level scoping — `list_students` never sees the caller's claims, so it returns the whole tenant roster to anyone who passes the permission check.

## Severity notes

- This is a broken-access-control / tenant-wide PII disclosure: a parent sees every student's name, admission number, and guardian identity — and the **CSV export** endpoint (`router.py:328`) reuses the same `students:read` gate, so a parent can also download the full roster.
- The same pattern almost certainly applies to the other broad keys: `/admin/fees`, `/admin/attendance`, `/admin/communication`, `/admin/circulars` are likely equally reachable by parents. Worth verifying whether those endpoints scope by caller.

## Fix direction (when you're ready)

The clean fix is at the source: strip the five admin-plane keys from the `parent` role and let parents rely solely on `parent:*` self-scoped permissions. Sidebar and routes then self-correct since they key off permissions. One caution before doing it: check whether any parent-facing page or endpoint actually depends on those broad keys (e.g. if `ParentFeesPage` or circulars endpoints are gated on `fees:read`/`circulars:read` rather than a `parent:*` key, removing them naively would break parent features) — that dependency check should be the first step of the fix.
