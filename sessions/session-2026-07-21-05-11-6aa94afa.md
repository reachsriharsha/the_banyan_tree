## Can you set more than 1 academic year as active?

**No.** The system enforces **exactly one active academic year at all times**. This is a core constraint validated in the test suite (`test_m2_01_a3_activate_exactly_one`). When you activate a year:
- If another year was previously active, it's automatically deactivated
- The newly activated year becomes the single active one
- There can never be zero or multiple active years simultaneously

## Why is setting an academic year as active important?

The active academic year serves as the **system-wide default** for several critical functions:

1. **Defaults for new records** — When teachers/admins create students, classes, fees, invoices, or reports, the system defaults to the active year unless they explicitly choose a different one.

2. **Clarity on "current session"** — It makes "the current school session" unambiguous across the entire app. Everyone sees the same active year, preventing confusion about which year's data is being viewed or modified.

3. **Dashboard & reporting** — Views and dashboards typically start by showing data from the active academic year.

4. **Backwards compatibility** — Having exactly one active year keeps the system predictable; code and UI can safely call `get_active_year(db)` and know it will return one year (or None if none has been set yet).

In short: the active year is the **primary working context** for the school. Changing it switches which academic session the system operates in by default. Teachers see it to know the current session; school-admins flip it when transitioning from one year to the next.
