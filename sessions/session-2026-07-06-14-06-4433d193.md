## Assistant (2026-07-06T14:13:04)

SQLite is a great fit — single portable file, no formulas to break, and I can query it for any report. Here's the refined design:

**One file: `portfolio.db`**

Tables:

- `goals` — retirement, children (education + marriage), cushion; each with target amount + target year
- `assets` — each PPF account, stock, MF, and bank account, mapped to a goal (basket per goal)
- `transactions` — appended whenever you invest: date, asset, amount
- `snapshots` — monthly (10th–15th): asset, month, current value. Bank balance goes here too — it's just another asset in the cushion basket

**Workflow:**

1. *Anytime you invest:* tell me in chat → I insert a transaction row
2. *Monthly (10th–15th):* you give me current values (PPF balance, stock/MF values, bank balance) → I insert snapshot rows and regenerate the dashboard
3. *Dashboard:* an HTML file rebuilt from the db each month — one card per goal with on-track %, plus overall net worth trend, invested vs. current value (so you see gains), and asset mix

**On-track % per goal** = current basket value ÷ expected value by now, where expected assumes steady progress from start date to target year. Above 100% = ahead. The cushion goal probably has no target *year* — for that one a simple % of target makes more sense (e.g., target = 12 months of expenses). Dashboard can handle both styles.

Portability bonus: the .db file lives in your project folder, works with any SQLite tool on any machine, and a CSV export is one command away if you ever want out.

That's the full design. When you're ready to build, I'll need: target amount + year for each goal, your asset list with goal mapping, and current values as the first snapshot. Want to start now or later?

## Assistant (2026-07-06T14:16:25)

A self-contained app pairs nicely with the SQLite decision. Two realistic ways to do it simply:

**Option A — single HTML file** (`tracker.html`)
One file, opens in any browser, no install. Uses sql.js (SQLite compiled to run in browser) to open your `portfolio.db`, with forms for adding transactions/snapshots and the dashboard rendered on the same page. With Chrome/Edge it can save directly back to the .db file. Ultimate portability: two files (app + db) on a USB stick and you're set. Limitation: needs a Chromium browser for smooth save-back; Safari/Firefox would make you re-download the db each save.

**Option B — single Python file** (`tracker.py`)
Run `python tracker.py` → opens a local page in your browser with the same forms + dashboard, reading/writing `portfolio.db` directly. No save-back quirks, works with any browser. Needs Python installed (Macs have it).

Both are one app file + one db file, no server, no accounts, no dependencies beyond the browser/Python. Complexity is about the same; it's really about whether you'd rather double-click an HTML file or run a Python command.

Your instinct is right. Sensible rule: track liabilities that are **large, long-term, and shrinking toward zero** — skip anything rolling/self-clearing.

**Include:** home loan (outstanding principal), plus any car/personal/education loan if it runs multi-year.

**Skip:** credit cards (rolling, paid monthly — noise, not net worth), utility dues, short-term borrowings. If you ever carry a card balance beyond a couple of months, that's the signal to add it.

**How it fits the design:**

- Liabilities sit outside goals — they don't belong to any basket. Your goal progress stays purely asset-based (you're funding retirement regardless of the loan).
- In the Monthly Update you'd enter one extra number: **outstanding principal** (from your loan statement/app). Just principal — interest is cost, not a balance.
- Dashboard changes: headline becomes **Net worth = assets − liabilities** (with assets and liabilities shown separately), plus a small loan card showing outstanding, % repaid, and a shrinking bar — the mirror image of a goal.

One thing worth having: the trend chart becomes more meaningful — you see net worth rise from both investments growing *and* loan shrinking.
