## The bug: delimiter mismatch (comma vs semicolon)

The importer splits the `subjects` field on **semicolons**, but your CSV separates subjects with **commas**.

`backend/app/modules/staff/service.py:644`:
```python
names = [s.strip() for s in (raw.get("subjects") or "").split(";") if s.strip()]
```

Your CSV row 2 has `"General Knowledge, Art, Music"`. Because the code splits on `;`, the entire quoted string is treated as **one** subject name: `"General Knowledge, Art, Music"`. That single string matches no subject, so it's reported as missing.

The error message *looks* like three unknown subjects only because `_resolve_subjects_by_name` joins the missing list with `", "` (line 155) — the same separator — so one comma-containing name is indistinguishable from three names in the output.

## Proof from the `eea` tenant DB

I checked `erp_t_eea.subjects`. Almost every subject you listed **already exists**:

| In your CSV | In DB? |
|---|---|
| General Knowledge | ✅ exists |

| **Art** | ❌ **not found — the subject is named `Art & Craft`** |

Since English/Mathematics/Science/Social Studies all exist yet every single row still errored, the failure can't be "subjects missing" — it's purely the comma-vs-semicolon parsing. (If subjects were genuinely missing, the rows with valid subjects would have imported fine.)
