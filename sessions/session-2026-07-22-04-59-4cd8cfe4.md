A nice bonus of the fix: the frontend `errorDetail()` helper happens to cover all three error shapes the backend can produce:

1. **`ProblemDetail`** (above) — `detail` is a string at top level → extracted

3. **422 validation errors** — FastAPI puts an *array* in `detail` → the `typeof === 'string'` check rejects it, falls back to the old `"422 Unprocessable Entity"` message

So the contract lines up on both sides with the frontend-only change.
