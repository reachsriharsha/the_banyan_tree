The seed succeeded — both databases were recreated and seeded, including the two receipt PDFs (`pay_chq_1`, `pay_rzp_1`).

The failure wasn't in the seed logic. The seeding step generates receipt PDFs via WeasyPrint, which loads GTK system libraries (`libgobject-2.0`) at runtime, and macOS's dynamic linker doesn't search Homebrew's `/opt/homebrew/lib` by default. This is the same root cause as the known m3_08 receipt E2E flake. The library is installed on your machine — it just wasn't findable.

The working command is:

```bash
cd backend
DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib .venv/bin/python -m app.dev_db recreate --seed
```

Two things worth knowing for next time:

- Any process that renders receipt PDFs (the seed command, the backend API server) needs `DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib` in its environment. If you want it set permanently, add `export DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib` to your `~/.zshrc` (or `~/.bashrc`).
- One caveat with your original invocation: the shell prompt showed `(akshara-backend)` but the traceback ran through `/Library/Frameworks/Python.framework/Versions/3.14` with the `backend/.venv` packages, so it did use the right site-packages — the env var was the only missing piece.
