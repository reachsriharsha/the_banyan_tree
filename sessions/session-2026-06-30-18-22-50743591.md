# Company Quick Scan (SOIC 30-Minute Deep Dive)

Purpose: Take a company name (or uploaded annual report) and produce a structured fundamental verdict in ~30 minutes of analysis time. This is the **first filter** before any deeper research.

## Inputs required
- Company name + ticker (NSE/BSE for India, NYSE/NASDAQ for US)
- Latest Annual Report PDF (ask user to upload, or fetch from BSE/company IR page)
- Optional: Screener.in URL (India) or 10-K link (US)

If the AR is missing, STOP and ask the user to provide it. Do not fabricate financials.

## Workflow (run in order)

### Step 1 — Locate the Annual Report
Confirm the most recent AR (FY ending). For India use BSE filings; for US use SEC EDGAR 10-K.

### Step 2 — 12-Point Annual Report Analysis
Read the AR and answer:
1. What does the company do? (1 paragraph, plain English)
2. Business segments and revenue mix (%)
3. Geography mix (%)
4. Customer concentration (top 5 / top 10)
5. Promoter / management background and pledging
6. Capex cycle status (expansion, maintenance, idle)
7. Working capital trend (debtor days, inventory days, cash conversion)
8. Debt position and interest coverage
9. Key risks disclosed by management
10. Related-party transactions (size, nature, recurring?)
11. Auditor changes / qualifications in last 3 years
12. Strategy and guidance stated by Chairman/MD letter

### Step 3 — 10-Point Forensic Red Flag Scan
Rate each as **GREEN / AMBER / RED**:
1. Cash flow vs PAT divergence (CFO/PAT < 0.7 over 3 yrs = RED)
2. Receivables growing faster than revenue
3. Inventory growing faster than revenue
4. Contingent liabilities vs net worth
5. Promoter pledging trend
6. Auditor qualifications
7. Related-party transaction size
8. Goodwill / intangible bloat
9. Frequent equity dilution
10. Subsidiary losses absorbed quietly

### Step 4 — Piotroski F-Score + DuPont
Compute Piotroski (0–9) and decompose ROE = Net Margin × Asset Turnover × Leverage. Compare 3-year trend.

### Step 5 — Bear Case
Write the strongest argument **against** owning the stock in 5 bullets. Be honest and aggressive.

### Step 6 — Verdict
One of: **BUY-WORTHY (deep-dive next)**, **WATCH (revisit on trigger)**, **PASS (do not pursue)**. Justify in 3 sentences.

## Critical data rules
- **Never calculate P/E from quarterly PAT.** Always pull TTM P/E from Screener.in (India) or the 10-K/quarterly filings (US).
- **10% divergence rule**: If your computed metric diverges >10% from Screener.in, trust Screener.in and re-check your math.
- All financial figures must cite the source page of the AR or Screener URL.

## Output format
Save as `<TICKER>_quick_scan_<YYYYMMDD>.md` in the user's workspace folder. Use the headings above. End with the Verdict and a list of follow-up questions for a deeper dive.

## Composability
After this skill: run `concall-analyzer` on last 4 concall transcripts, then `growth-triggers-onepager` if verdict is BUY-WORTHY or WATCH.

# Concall Analyzer

Three modes — pick based on input count and user intent.

## Mode A — Concall Brief (default for 1 transcript, fast)
9 sections:
1. Headline numbers (revenue, EBITDA, PAT, margin, YoY/QoQ)
2. Segment performance
3. Demand commentary
4. Margin drivers / pressures
5. Capex and balance sheet update
6. Guidance (quote management verbatim)
7. New announcements (orders, products, deals)
8. Analyst Q&A — top 3 sharp questions and management's answers
9. Key takeaway in 2 sentences

## Mode B — Concall Deep Dive (12 sections, when user asks for "deep" or single critical quarter)
Adds to Mode A:
10. Confidence Language Audit (see taxonomy below)
11. What was NOT answered / dodged questions
12. Changes in tone vs prior call

## Mode C — Walk the Talk (when 4+ concalls provided)
Build a credibility scorecard:
- Extract every forward statement from concall N-3
- Check if it played out by concall N
- Score **+1 for beat**, **0 for partial**, **-1 for miss**
- Aggregate score → Management Credibility Rating (HIGH / MEDIUM / LOW)
- Flag any pattern of repeated optimism without delivery.

## Confidence Language Taxonomy (apply in all modes)
- **HIGH conviction**: "We will", "We have", "We are", "This year we deliver"
- **MEDIUM conviction**: "We expect", "We should", "We are confident", "We anticipate"
- **LOW conviction**: "May", "Could", "Endeavor to", "Aspire", "Hopefully"

Tag each guidance statement with HIGH/MEDIUM/LOW and warn the user when LOW-conviction language is used for material claims.

## Inputs
- 1+ concall transcript files (PDF or text). If only company name is given, ask the user to upload transcripts (Quartr / company IR page).

## Output
Filename: `<TICKER>_concall_<QUARTER>_<mode>.md` saved in the workspace folder. For Walk the Talk: `<TICKER>_walk_the_talk_<YYYYMMDD>.md`.

## Critical rules
- Always quote management verbatim in quotation marks for guidance statements; never paraphrase guidance.
- Cite the page or timestamp of each quote.
- Do not invent numbers — if the transcript doesn't say it, write "not disclosed".

# Scenario Valuation (Base / Bull / Bear with % Gap to CMP)

Purpose: turn what management actually said (annual report, concall, investor presentation, exchange filings) into a defensible **forward Revenue → PAT → EPS** build, then value it three ways — **Bear, Base, Bull** — and report the **upside/downside % gap to the live CMP**. The whole point is traceability: a reader should be able to see exactly which sentence in which document produced every number.

The output is a single markdown file, heavy on tables, that ends with a scenario scoreboard.

## Core principles (read first)

1. **Every assumption traces to a source.** Each growth rate, margin, capacity, order book or multiple must cite where it came from: `AR FY25 p.42`, `Q4FY25 concall`, `Investor PPT Jun-25 slide 11`, or `peer median`. If you cannot source it, mark it `analyst est.` and keep it conservative. Never invent a number to fill a cell — write `not disclosed`.
2. **Separate the two valuation engines.** The user wants both shown, in their own sections:
   - **Section A — Fundamental Build:** forward Revenue × margin → PAT/EPS, then apply an exit multiple. Three levers move per scenario (growth, margin, exit multiple).
   - **Section B — Multiple Re-rating:** hold ONE forward EPS (the Base build) and vary only the multiple. This isolates "what if the market just re-rates the same earnings".
   These can and often will give different answers — that is informative, not a bug. Show both, then reconcile in the verdict.
3. **Pick the multiple from the sector, not from habit.** Different sectors are valued on different ratios (a bank on P/B, a cement co on EV/tonne, an IT firm on P/E). Read `references/sector-multiples.md` to map the company to its sector and pull the right primary ratio + a cross-check ratio.
4. **Anchor scenarios to evidence, not to symmetry.** Bull is not "Base + 20%". Bull = management's stated best case actually lands (full capacity utilised, guidance hit, margins at the top of the stated band). Bear = the disclosed risks bite (demand miss, margin compression, delayed capex). Base = the most likely path. Justify each lever with a source.
5. **Get CMP live.** Use `WebSearch` (load via ToolSearch if needed) to fetch the latest price and market cap before computing gaps. Note the date/time and source. If the search is blocked or stale, ask the user for the CMP rather than guessing.

## Inputs

- Company name + ticker (NSE/BSE for India; NYSE/NASDAQ for US).
- At least one primary source: latest annual report, recent concall transcript(s), investor presentation, or exchange filing. More is better — the build is only as good as the disclosure behind it.
- Optional but ideal: the markdown outputs of `company-quick-scan`, `concall-analyzer`, `growth-triggers-onepager` — reuse their extracted facts instead of re-reading from scratch.

If no primary source is available at all, STOP and ask the user to upload one. A valuation with no disclosure behind it is just a guess.

## Workflow (run in order)

### Step 1 — Anchor facts
Establish and record, in a small table:
- Sector (and sub-sector) → determines the valuation ratio (Step 2).
- **CMP** + market cap (live, via `WebSearch`; cite source + timestamp).
- Shares outstanding (fully diluted) — from the AR/latest filing.
- Latest reported / TTM figures: Revenue, EBITDA, PAT, EPS, net debt, book value, and the relevant per-unit base (capacity in tonnes, beds, subscribers, AUM, GWP, etc. — only what the sector needs).
- The stock's **current multiple** on the relevant ratio (e.g. current P/E, current EV/EBITDA, current P/B) and, if available, its **own 5-year median** and **peer median**. These three numbers frame what a "fair" exit multiple is.

### Step 2 — Map sector → valuation ratio
Read `references/sector-multiples.md`. Pick the **primary ratio** for the sector and one **cross-check ratio**. Note the typical multiple range (own history vs peers). For multi-segment companies, each segment may use a different ratio — that flows into Step 5 (SOTP).

### Step 3 — Build the forward estimate (the assumption ledger)
This is the heart of the skill and the part the user cares most about: **show your work, sourced.**

Choose a forecast horizon (default: end of the next full financial year the company guides to — usually FY+1 or FY+2; state which). Build forward Revenue, then walk down to PAT and EPS. Present it as an **Assumption Ledger** table — one row per driver, with the source and the quote/figure that justifies it:

| Driver | Current | Assumption | Source (doc + page/slide/quote) | Scenario sensitivity |
|--------|---------|-----------|--------------------------------|---------------------|
| Volume / capacity | … | +X% (new line commissioned Q3) | Investor PPT Jun-25 slide 8 | Bull: full util.; Bear: ramp delay |
| Realisation / pricing | … | flat / +Y% | Q4FY25 concall, MD quote | … |
| Revenue (derived) | … | ₹… cr | = volume × realisation | … |
| EBITDA margin | …% | …% (guided band 18–20%) | Concall guidance verbatim | Bull 20% / Bear 17% |
| Depreciation, interest, tax | … | … | AR FY25 schedules | … |
| **PAT (derived)** | … | ₹… cr | walk-down | … |
| Shares (diluted) | … | … | AR | dilution if QIP flagged |
| **EPS (derived)** | … | ₹… | = PAT / shares | … |

Quote management verbatim for any guidance figure (in quotation marks). Tag the conviction of each guidance statement using the concall taxonomy when relevant — "we will" (HIGH) vs "we aspire to" (LOW) — and lean conservative when the language is soft. Build the **Base** column first; Bull/Bear are deltas off it, each justified.

### Step 4 — Section A: Fundamental Build valuation
For each scenario (Bear / Base / Bull), compute the forward per-share value using the sector's primary ratio and the methods in `references/valuation-methods.md`:
- **P/E sectors:** Target price = forward EPS × exit P/E.
- **EV/EBITDA sectors:** Target EV = forward EBITDA × exit EV/EBITDA → subtract net debt → ÷ shares.
- **P/B sectors (banks/NBFC):** Target price = forward BVPS × exit P/B (cross-check with ROE/justified P/B).
- **Per-unit sectors:** Target EV = units × EV/unit → bridge to equity → ÷ shares.

Each scenario flexes **three levers**: the growth (→ revenue), the margin (→ PAT/EBITDA), and the **exit multiple** (Bear below own median, Base at median, Bull toward peer top / re-rating). State the exit multiple chosen and why.

Present as a table:

| Scenario | Fwd Revenue | Margin | Fwd PAT/EBITDA | Fwd EPS/BVPS | Exit multiple | Target price | Gap to CMP |
|----------|------------|--------|----------------|--------------|---------------|-------------|-----------|
| Bear | … | … | … | … | …x | ₹… | −…% |
| Base | … | … | … | … | …x | ₹… | +…% |
| Bull | … | … | … | … | …x | ₹… | +…% |

### Step 5 — Section B: Multiple Re-rating valuation
Hold the **Base-case forward EPS (or EBITDA/BVPS)** fixed and vary ONLY the multiple. This answers "if earnings land as expected, what does a de-rate / hold / re-rate do to the price?"

| Multiple scenario | Multiple | Basis | Target price | Gap to CMP |
|-------------------|----------|-------|-------------|-----------|
| De-rate (Bear) | …x | below own 5y median | ₹… | −…% |
| Hold (Base) | …x | own 5y median | ₹… | +…% |
| Re-rate (Bull) | …x | peer top / historical peak | ₹… | +…% |

### Step 6 — Part Evaluation (SOTP) — only when segments exist
Detect whether the company is **multi-segment, a holding company, or has material listed/unlisted subsidiaries** (check segment reporting in the AR and the investor presentation). If yes, build a sum-of-the-parts:

| Segment / asset | Metric (EBITDA / PAT / stake value) | Ratio applied | Value (₹ cr) | Per share |
|-----------------|------------------------------------|---------------|--------------|-----------|
| Core business | … | …x EV/EBITDA | … | … |
| Subsidiary A | … | …x P/E | … | … |
| Listed stake B | mkt value × stake | holdco discount …% | … | … |
| Net cash / (debt) | … | — | … | … |
| **SOTP value** | | | **…** | **₹…** |
| Gap to CMP | | | | +…% |

Apply a holding-company discount (typically 20–50% in India) to listed-stake value and say what discount you used and why. If the business is a single segment, write "Single-segment business — SOTP not applicable; valued as one entity in Section A" and skip the table.

### Step 7 — Scenario scoreboard + verdict
Consolidate everything into the headline table the user opens the file for:

| Scenario | Method | Target price | Gap to CMP | What has to be true |
|----------|--------|-------------|-----------|---------------------|
| Bear | Build + de-rate | ₹… | −…% | demand miss, margin to bottom of band |
| Base | Build at median | ₹… | +…% | guidance broadly met |
| Bull | Build + re-rate | ₹… | +…% | full capacity + re-rating |
| SOTP (if used) | Parts | ₹… | +…% | — |

Then 3–4 sentences: the risk/reward (how much downside to Bear vs upside to Bull), which scenario is most probable and why, and the single biggest swing factor. Reconcile Section A vs Section B if they diverge materially. End with the disclaimer: *Research only. Not investment advice.*

## Output format
Save as `<TICKER>_valuation_<YYYYMMDD>.md` in the user's workspace folder. Use this top matter, then the sections above:

```

*As of <date> | CMP: ₹/$X (source, timestamp) | Mcap: … | Sector: … | Primary ratio: …*
```

## Helper script
`scripts/valuation_calc.py` does the deterministic arithmetic — the EV↔equity bridge, per-share conversion, and % gap — so you don't make manual errors across nine scenario cells. ## Critical rules
- **Never compute the exit P/E off a single quarter's PAT.** Use forward full-year EPS; pull current/median multiples from a live source or the user's data, not from quarterly annualisation.
- **CMP must be live and dated.** A gap % is meaningless against a stale price.
- **Conservatism on soft guidance.** When management says "aspire / hope / could", treat it as Bull-only upside, not Base.
- **Show the gap with sign and magnitude** (e.g. `+34%` / `−18%`) for every scenario against the same CMP.
- **Do not fabricate.** Missing input → `not disclosed`; estimated input → label `analyst est.` and keep it conservative.
- **State units and currency** (₹ cr / $ mn, per-share in ₹/$). Don't mix consolidated and standalone figures silently.

### 2. Executive summary (top of page, always visible)

- Piotroski score (number + bar)

## Critical rules

- **Preserve citations.** Any quote or metric that had a source page in the markdown should keep the citation visible in a small muted span.

- **Deterministic parsing.** The three input skills follow fixed templates — parse by headings (e.g., `## Trigger Scoreboard`) rather than by fuzzy matching.
- **Offline-viewable is a hard requirement** except for the Chart.js CDN script tag.
