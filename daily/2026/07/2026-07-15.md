## Session 2 — Database Connection Architecture Analysis

**Project:** Akshara (School Management)

**Question:** With ~60 tables, does each have its own connections? Will this stress the DB? Are connections always present when backend starts?

**Analysis (No Code Changes):**
- **Tables don't have connections** — connections belong to databases, not tables
- All 60 tables in `erp_t_dev` share same SQLAlchemy connection pool
- Number of connections determined by engine pool settings, not table count

**Backend Connection Setup:**
- `control_engine` (sync): for `erp_control` DB provisioning/scripts (at import, `app/db.py:76`)
- `dev_tenant_engine` (sync): for dev-only `erp_t_dev` access (at import, `app/db.py:77`)

**Key Point:** Pool is small, configured per engine; tables all share those connections. No per-table overhead.

**Status:** Architecture explained; no changes needed.
