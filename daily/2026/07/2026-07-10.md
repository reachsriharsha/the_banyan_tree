## Session 1 — Seed Command Debugging (DYLD Library Issue)

**Project:** Akshara (School Management)

**Issue:** `python -m app.dev_db recreate --seed` failed with WeasyPrint unable to load `libgobject-2.0` library

**Analysis (No Code Changes):**
- WeasyPrint requires native C libraries (Pango/GObject) from Homebrew
- Libraries exist on machine (`/opt/homebrew/lib/libgobject-2.0.dylib` confirmed)
- Issue: macOS dyld doesn't search `/opt/homebrew/lib` by default
- Solution: Set `DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib` when running seeding command
- Note: `start_api_server.sh` already sets this for the backend server, but direct Python invocation doesn't inherit it

**Root Cause:** Same as known m3_08 receipt PDF E2E flake

**Fix:**
```bash
DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib python -m app.dev_db recreate --seed
```
