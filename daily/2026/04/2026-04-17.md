# 📝 Notes

**minimalist-app — auth feature (feat_auth_001 merged)**

Designed and shipped the authentication foundation for minimalist-app.

_Decisions made_

- **Session model:** Redis-backed httpOnly cookie, 1-day absolute TTL, AOF persistence — chose over JWT for security, revocation support, and no DB-per-request overhead
- **Role model:** many-to-many users ↔ roles, seeded with `admin` + `user`
- **Identity model:** `users` + `auth_identities` table, auto-link on verified email
- **OAuth flow:** backend-driven Auth Code + PKCE (provider-agnostic, testable)
- **OTP delivery:** `ConsoleEmailSender` (dev) + `ResendEmailSender` (prod), 6-digit, 10-min expiry, 5-attempt lockout, 1/min + 10/hour rate limits
- **Deployment docs path:** `docs/deployment/` (not top-level `deployment/`)

_Feature decomposition_

- `feat_auth_001` — foundation (roles, identity, session infra) ← **merged today**
- `feat_auth_002` — email OTP login
- `feat_auth_003` — Google OAuth login
- `feat_frontend_002` — auth UI
